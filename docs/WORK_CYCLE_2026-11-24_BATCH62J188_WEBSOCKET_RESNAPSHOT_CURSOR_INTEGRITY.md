## 1. Defect found

Backend `backend/app/main.py` emits `market_data.ohlcv.resnapshot_required` with a decimal-string `snapshotCursor`, followed by a replacement snapshot whose `cursor` is the durable cursor captured for that same subscription. The frontend transport validated that each cursor was a decimal string but did not compare the two values. This left a continuity check missing at the server-directed resnapshot boundary.

## 2. Runtime correction

Commit `af9020ba6bbc98110a237b18caac9920570cf1ed` — `fix: bind replacement snapshots to resnapshot cursor`.

File: `src/services/ohlcvWebSocketClient.ts`.

- Require a non-empty resnapshot reason.
- Retain the expected `snapshotCursor` after the resnapshot instruction.
- Require the replacement snapshot to carry a cursor exactly equal to that expected cursor.
- Reject a mismatched or missing cursor before publishing the replacement snapshot.
- Clear the expectation only after the replacement snapshot passes validation.

The comparison is string-exact for the protocol's canonical unsigned decimal cursor representation; it does not coerce a 64-bit cursor through JavaScript Number.

## 3. Regression coverage

Commit `22c9ab4a0e97383520670a9af42a2f9ef35f6d62` — `test: reject mismatched resnapshot watermarks`.

File: `src/services/ohlcvWebSocketClient.test.ts`.

Two new negative cases:
1. A replacement snapshot whose cursor differs from the server-advertised resnapshot watermark is rejected; no snapshot callback is published.
2. A replacement snapshot omitting its required durable cursor is rejected; no snapshot callback is published.

The existing positive case still verifies that an exact matching cursor is accepted. No backend wire format, indicator formula, chart renderer, or Android application runtime was changed.
